How the work is presented

The workflow comes first.

Technology is useful when it fits a real setting. These case notes begin with the task and the people using it, then make the implementation and its limits visible.

Understand the setting

Describe the learner or operator, the task, the constraints and the person responsible for using the result.

Make adaptations concrete

Explain what changes: choice count, target size, input method, pacing, feedback or the handling of missing data.

Show evidence and boundaries

Keep source, demonstration, research proposal and measured outcome distinct. Synthetic examples make the workflow reviewable without exposing student information.
