Literacy Instruction and Response Tracking

Classroom activities are used on a Smartboard; keyboard controls are an unused backup. Browser/pointer checks are reported separately from physical-device validation.

Creator and classroom workflow designer: Zachary Halaby. Developed and iterated with AI coding assistance.

An engineering demonstration of a practical classroom problem: a correct answer after modelling or a retry should not silently replace the first response. Missing observations, access support and interrupted sessions also need distinct meanings.

This small package is derived from recovered Mother Hen and Jungle Book source. Six functions and four constant initializers are retained from the actual applications. The interface, scenario fixtures and stricter input guards are new. It is not either full classroom application, and none of their student information or media is included.

Try it

Open index.html in a current desktop browser. There are no dependencies to install, network calls, logins, recording permissions, storage, file imports or exports. Every selectable scenario is invented; there is no field for a learner's identity or real record.

Try Correct after retry: the initial response remains incorrect even though the eventual response is correct. Compare AAC access only with Prompted success. Turn off adult confirmation to see missing evidence remain unknown. Change the choice count from two to four to see the comparison conditions separate.

Keyboard users can Tab between labelled controls and activate the example buttons with Enter or Space. There are no timers or animations. The result explanation is announced through a live region.

Retained code and new work

evidence-core.js contains these recovered functions:

  • Mother Hen: promptEvents, assistanceBeforeInitial, answerHelpBeforeInitial, independence, eligible.
  • Jungle Book: conditionSignature, plus its hash initializer.

The original rules distinguish AAC/activation access from answer cues, require explicit support confirmation, keep practice out of initial comparisons, and represent task conditions such as wording, response method and choice count. The demo adapter additionally rejects missing initial outcomes, unknown prompt codes, legacy versions and interrupted records before interpreting a result.

PROVENANCE.json records archive/HTML hashes, script indexes and exact function hashes. It contains no local account path or private records. Functions are copied as code; this UI is a new reconstruction around them. The noncryptographic condition signature is an internal grouping aid, not a security or assessment-equivalence guarantee.

Privacy, status and verification

All original rosters, profiles, goals, logs, name recordings, photographs, book text, artwork, audio/video, remote URLs and storage/import/export/capture paths are excluded. No real source records were sampled, transformed or fitted to create the demo scenarios.

Seven Node tests cover confirmation, access-versus-answer help, first-versus-eventual outcomes, timing, missingness, interruption/practice and condition changes. Nine local browser checks cover representative paths, keyboard operation, no persistence/network activity and narrow layout. A synthetic screenshot was visually reviewed. See VALIDATION.md.

The retained classifier is a prototype rule, not a validated measure of learning, disability or mastery. The original full apps contain richer reporting and policy assumptions that were not adopted here. This demo makes no decisions about actual learners and reports no learning gains, adoption metrics or classroom effectiveness.

Touch interaction review — November 27, 2026

The whole labelled checkbox row is now a minimum 48 px high tap target, matching the large preset buttons and selectors. Tapping the label area toggles explicit confirmation without changing the underlying evidence rules. Repeated preset taps remain idempotent; there is no automatic advance or response timer.
