Teddy Book Adventure — task logic reference

Creator and classroom workflow designer: Zachary Halaby. Developed and iterated with AI coding assistance.

The recovered application connects a narrated story with printed-word choices, spelling, object selection and ordering tasks. Its code allows either dragging or a two-step select-and-place interaction. The response handler records attempts and carries a support flag when a hint or earlier incorrect attempt has occurred.

Package status: inspected source reference, not a restored story application. No original story, art, voice or music bank is included. The small module here demonstrates task-option behavior using invented inputs, without rebuilding an unrelated interface and presenting it as the original app.

Retained source

task-options.cjs retains the original shuffle, currentCorrect and makeOptions function bodies. A new adapter supplies a synthetic task, its current position and used item IDs. It validates spelling/sequence bounds before invoking the functions.

The source logic selects the next letter for spelling, excludes already-used items in ordering activities and derives distractor words from a supplied sentence. This is different from the timed routine in Teddy Sequence Party; the two are not treated as duplicate files.

Static inspection also found response guards for pause/removal/used items, support-aware retry logging and a summary based on those recorded flags. The original summary's “independent” label is an internal rule result; it is not a validated measure of a learner's ability or a complete record of adult assistance.

Requires an existing Node.js installation, with no added packages. Tests passed for spelling order, correct-option availability, unique distractors, used-item exclusion, sentence-based choices and an invalid-position guard. All fixture words and sequences are invented. The full rendering, audio, drag handling, timing and accessibility of the original were not executed or validated.

This reference illustrates how a classroom task changes state after a response and how different response modes can share task rules. No adoption or educational-effectiveness claim is made. Original media are excluded; a software license for the selected code has not yet been chosen. No publication or upload is part of this package.
