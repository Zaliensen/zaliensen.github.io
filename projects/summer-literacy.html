Summer literacy: task routing and consistent visual clues

Creator and classroom workflow designer: Zachary Halaby. Developed and iterated with AI coding assistance.

This is a source-backed case study of the selected Week 1 Summer Literacy Smartboard Game v32, no wrong visuals application. It documents the actual recovered implementation. It is not a restored app or a new generic demonstration, and no original HTML or media is distributed in this package.

Classroom problem and implemented approach

The application combines country-themed reading and literacy tasks with paired team turns, different response demands, prompts, teacher controls and result reporting. A later set of patches addresses a specific usability problem: a clue picture or caption could accidentally depict a wrong answer or contradict the task.

The final visual-selection layer gathers correct terms, proposes related visuals, rejects captions associated with wrong answers, removes duplicates and limits the visual set. Its task sanitizer also deduplicates distractors and adds a fallback if fewer than two choices remain. This is an implemented attempt to keep the instruction, visual clue and response options consistent; it is not evidence that every generated task was correct in classroom use.

Why this package contains documentation

This source connects personalized setup, named logs and CSV export with remote media, speech support and an optional microphone/noise-meter path. Removing a few visible names or images would not establish that every later override respects the same boundary. The complete original was not executed, and no original records, media, names or capture code were copied here.

A source-preserving public edition needs one coordinated integration pass: identify the final active implementations; replace personal setup with fixed fictional participants; remove record exports, microphone access and remote media; then test task generation, hints, turn progression and report semantics across the configured activities. Those changes are outstanding. A rushed alternative interface would obscure the actual engineering work, so this case study preserves the distinction.

Portfolio use and relationship

Use this to discuss how user feedback can produce a concrete correction: keep helpful visual cues while preventing a clue from pointing toward a wrong option. The layered patch history also supplies an honest refactoring example—make the effective behavior explicit and test the boundary between generation, rendering and logging.

This is distinct from the World Literacy Board Game: the latter uses a board path and landing activities, while this application centers on generated task families, paired turns and result logs. They share subject matter, not a claim of interchangeable code. Keep country variants together within a consolidated classroom-tools repository and list this as documentation until a clean runtime passes review.

No classroom outcomes, deployment scale, accessibility conformance or validated assessment claims are made. The Sent timestamp is the latest matching lead found in the bounded search, not proof that no later version exists elsewhere. A project software license remains to be selected.
