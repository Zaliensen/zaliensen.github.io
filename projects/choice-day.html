Choice Day

Creator and classroom workflow designer: Zachary Halaby. Developed and iterated with AI coding assistance.

An adult-supported classroom activity for learners who may respond through speech, pointing, AAC, partner selection or passing. The recovered Face’s Choice Day / Choice Club project combines story recall, name/letter activities, feelings, counting and teacher guidance.

This package provides a new synthetic portfolio reconstruction of two workflows: making a personal choice and counting three garden markers. Its generic symbols and prompts replace the original character artwork and classroom materials. It is not a complete reproduction of the recovered lesson.

Run and demonstrate

Open index.html in a current browser. No setup, account, network connection or stored learner record is required. Select a support level, try Show a model, make a response, then use Confirm response and Next activity separately. The counting task ignores repeat presses on the same object. Challenge mode accepts a typed total; the teacher interprets the response rather than the demo assigning a grade.

Keyboard users can Tab to each button and press Enter or Space. Larger text, stronger contrast, help and passing remain available. The content is synthetic and state disappears on reload.

Why the interaction is structured this way

The adult needs to distinguish showing how an activity works from receiving a learner's answer. Modelling therefore never enables confirmation. Acknowledging a response does not move the learner to the next screen. Teacher-controlled pacing leaves time for communication, correction or an additional attempt.

More support reduces the first activity to two choices and provides a counting cue. Standard support adds another choice. Challenge mode asks for a typed count. These are explicit interface adaptations; they are not a validated assessment of ability. Personal preferences have no correct or incorrect answer.

Recovered design evidence

The original answer-transition.js includes a modelling guard and a teacher option to remain on the page. Its default also schedules a celebration and automatic advancement. The reconstruction makes manual advancement the only path and removes animation and mandatory reward media.

experience-v2.js contains per-question support settings, labelled hotspots, a Set-based duplicate-count guard, typed totals, alternate responses and teacher notes. The template explains partner-assisted selection and keeps entered names in page memory. No real names or response records are included here.

Contents and architecture

The new demo uses index.html, styles.css and app.js with an explicit page/response/confirmation state. Its count state is a Set, preventing duplicate presses from adding another item. preview.png shows synthetic content.

source-reference/ preserves transition and activity modules for review. recovered-controller.js is extracted from the original template; inline SVG character artwork, HTML and CSS were omitted and the artwork helper is an empty reference stub. The references are not independently runnable and still name original lesson characters. They contain no embedded original media. SOURCE_MANIFEST.json describes extraction and original hashes.

Validation and next steps

Automated browser checks passed for model-without-submission, confirmation-without-advance, unique counting, pass, challenge input, empty-input guard and narrow layout. No external requests or page errors occurred in the scenarios. This is not a screen-reader, assistive-device or learner usability audit. See VALIDATION.md.

Further development should include an adult-led accessibility review and a concrete feedback/change cycle documented without student information. A software license has not yet been selected, and original media remain excluded. The new synthetic reconstruction is not evidence of earlier classroom results.
