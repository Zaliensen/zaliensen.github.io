Story Studio

Creator and classroom workflow designer: Zachary Halaby. Developed and iterated with AI coding assistance.

A classroom story-building project that turns a blank-page task into manageable choices. The recovered React application explores multiple participation modes, including touch, keyboard, partner support and experimental camera-based gaze selection.

This package contains a new, synthetic portfolio reconstruction plus selected recovered source. The reconstruction demonstrates three choices—character, setting and action—with explicit confirmation. It is not the full original app and does not demonstrate gaze accuracy or student outcomes.

Try the demonstration

Open index.html in a current desktop browser. There is no installation, account, camera, microphone, network request or saved learner record. Alternatively, serve this folder using python -m http.server 8080 --bind 127.0.0.1 and open http://127.0.0.1:8080.

Select a character, confirm, choose or pass a setting, and finish the story. Teacher controls offer two or four choices, larger text and stronger contrast. Manual scanning practice uses Space to move a highlight and Enter to select while the choice area has focus. It is a two-key demonstration; no single-switch hardware integration has been validated.

User need and adaptations

The design addresses different ways a learner may communicate a choice. Large choice targets, persistent labels, visible focus and a separate confirmation step reduce demands on precise pointing and rapid responses. Help and passing remain available. A partner can select on behalf of a learner using their established communication method. No timer advances the activity.

The recovered source supplies stronger evidence than the demo alone: src/accessibility/GazeTargetProvider.jsx defines 72-pixel touch and 96-pixel gaze target minima; src/engagement/engagementSettings.js exposes dwell/grace/target settings; and src/utils/gazeSmoothing.js includes outlier rejection and cursor smoothing. These are implementation features, not evidence of clinical effectiveness or accessibility conformance.

Architecture and package boundaries

The new demo uses index.html, styles.css and app.js. Its state is local to the page: step, selected answer and completed choices. Content is rendered as text, with decorative Unicode symbols and no external artwork. preview.png is a screenshot of synthetic content.

source-reference/ preserves selected React/Vite source, including the original app entry, story engine, choice logic, settings and gaze modules. It deliberately excludes media, generated asset directories, environment files, installed dependencies and Git history. It is a reference subset, not a complete runnable Vite checkout; package scripts refer to omitted build/validation tools. Do not treat running npm install here as a complete restoration procedure.
