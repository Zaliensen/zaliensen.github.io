Storybook Generator and Theater

Creator and classroom workflow designer: Zachary Halaby. Designed and iterated with AI coding assistance.

Actively developed prototype. Story wording, choice quality, illustrated theater integration, accessibility validation and performance remain ongoing work.

Explore the source and local setup

From manageable choices to a shared story

The project explores how a learner can build a story through choices, then experience those choices as a book and coordinated playback. Classroom use centers on Smartboard touch interaction; keyboard controls are a backup. The technical question is how to preserve the selected character, setting and actions as the content moves between views.

The recovered React source includes story plans, composition, validation, page controls and theater scene timing. The public review mode uses the fictional name Reader, the existing deterministic composer and a text-only theater. It runs locally without a model-provider account or camera. Original artwork is excluded, and the local prose is explicitly labeled as template composition.

Implementation and checks

A shared story plan feeds structured book pages and the playback adapter, keeping the active text and page controls together. The public source retains the optional AI-author integration for inspection; it requires explicit developer opt-in and is not deployed by this website. Experimental gaze code is retained as research and is disabled in the review interface.

The source release passed clean installation, local generation and mock-provider tests, a production build, and a complete eight-selection, twelve-page browser path. Navigation, reset, text synchronization and network/camera boundaries were checked. These were software checks, not validation on a physical Smartboard or proof of classroom outcomes.

Current limits and next work

Some generated wording needs editorial review. Original illustration integration and camera/gaze behavior remain outside the public demonstration. The retained story engine also produces a large JavaScript bundle. Further work includes content review, performance improvements and device-based testing. No adoption, learning-gain or accessibility-certification claim is made.
