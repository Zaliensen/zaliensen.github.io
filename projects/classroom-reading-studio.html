Classroom Reading Studio — neutral source-derived demo

Creator and classroom workflow designer: Zachary Halaby. Developed and iterated with AI coding assistance.

This offline activity presents printed words, supported choices and letter-by-letter word building. It demonstrates a predictable teacher-led sequence with a visible model, retry feedback, manual scanning and explicit teacher-supported completion.

The starting point was a recovered character-themed safety-sign reading application. Static review confirmed reading pages, adjustable choices, word-building tasks, turn controls, personalized media and response logging. The package here keeps a small inspected part of that task logic and rebuilds a neutral interface around new text. It is not a restoration of the original character/media experience.

Run locally

Open index.html directly in a current browser. No installation, server, account, API key or internet connection is needed. The demo includes three short printed-word pages and nine activities.

Choose one of three fictional turn labels and a choice-field size. Select a word to inspect its letters, answer a task, request a model or select teacher-supported completion. The teacher option is explicitly labeled as support; it does not count as an independent answer. Use Next only when ready. Reset discards the interactions in memory.

Keyboard access uses normal Tab/Enter buttons. With a choice focused, Right Arrow moves through choices; manual scan/select buttons are also provided. There is no timed dwell, autoplay, recording or automatic advance. Larger text and a single-column narrow layout are available. A teacher can read the text aloud; all original audio has been excluded.

These are printed-word exercises, not road-safety instruction, an independent-travel tool or an assessment of a person's readiness to navigate traffic. No original signs, book scans or franchise assets are shown.

What is retained

source-core.js retains the inspected escapeHtml function and adapts getChoiceItems from the recovered source. Its word-building choices include the next required letter; support settings vary the number of alternatives. The original global state is now an explicit function parameter, and invalid states are rejected before choices are generated.

The new app.js shell keeps turn-by-turn interaction, retries and teacher modeling while removing identity records and persistence. lesson-data.js contains newly written neutral material. All counters are temporary demo interactions, not recovered student outcomes.

No original roster, name audio, celebration audio, photograph, video, character graphic, book page, signed media URL, stored response or export is included. All media are excluded even where individual rights were not established. See PROVENANCE.md for the exact boundary.

Checks and interpretation

With an existing Node.js installation:

node tests/test-core.cjs

This requires only Node's standard library. Core and browser checks verify the choices, sequencing, support flags, manual scanning, completion/reset and direct file operation. See VALIDATION.md.

The project demonstrates Zachary Halaby's interface and classroom workflow design, including operational tradeoffs and separation of modeled versus unsupported responses. These source and demo checks do not establish real deployment, learning outcomes, accessibility certification or student-privacy compliance. The new preparation work is also AI-assisted. Third-party media are excluded, and a project software license has not yet been selected.

PRIVACY.md and LICENSE_STATUS.md describe the release boundary. This package is a portfolio demonstration with the source boundaries described here.
