PDF Slideshow Clicker

Public application source

The runnable application and bundled PDF.js files are available in the portfolio source repository. Run the local-server instructions below from that demo folder.

Creator and classroom workflow designer: Zachary Halaby. Developed and iterated with AI coding assistance. PDF rendering uses the separately credited Apache-2.0 PDF.js library.

A small classroom utility for presenting a local PDF one page at a time. The workflow gives a learner or teacher a clear advance action, optional sound and an optional video break after a chosen number of advances.

This is a revised implementation based on a recovered HTML prototype, with a synthetic four-slide mode for immediate review. No personal PDF, audio, video or student information is bundled.

Run locally

Open index.html directly to try the synthetic slides. For actual PDFs, run this command from the package folder with an existing Python 3 installation:

python -m http.server 8080 --bind 127.0.0.1

Open http://127.0.0.1:8080, select a PDF and press Open selected PDF. If Windows maps python to an older interpreter, use py -3 or the path to an installed Python 3 executable. No dependencies need to be installed. Local HTTP is required for the bundled PDF.js ES module and worker.

Files are read in browser memory; this app has no upload endpoint, analytics or response persistence. Optional media uses temporary object URLs that are released on return to setup. Each selected file is limited to 100 MB for this review version.

Interaction and adaptations

On the focused presentation surface, Space, Enter or Right advances; Left goes back. Normal buttons retain their standard keyboard behavior. Escape returns to setup. Previous, Next and Back to setup are always explicit controls. A video break provides playback controls and a keyboard-reachable Skip button.

Sound is optional. A still acknowledgement replaces the original confetti, so participation does not depend on tolerating motion or audio. Page status is announced through a live region. Extractable PDF text is available below the canvas; an image-only or poorly tagged PDF still needs an accessible alternative.

Changes from the recovered version

The original it.fixed.v12.html used a CDN PDF renderer, required a sound file to start, attached navigation to document-wide click/keyboard handlers, had duplicated Start markup and cached rendered pages without a bound. The revised app uses local PDF.js, scopes navigation to the stage, makes media optional, prevents overlapping advances, releases file URLs and returns to usable setup after a load error. It renders the current page instead of retaining a bitmap cache for every page.

app.js manages setup, rendering, navigation and media state; styles.css provides the responsive interface. vendor/pdf.min.js and vendor/pdf.worker.min.js are exact PDF.js 5.6.205 ES-module bytes with renamed extensions to avoid Windows MIME-type issues. Apache-2.0 license text is in vendor/PDFJS-LICENSE.txt. No original confetti library or media is included.

Evidence and validation

Recovery candidate C007 includes 18 HTML variants dated October 16, 2025. Zachary Halaby has confirmed ownership of the classroom project. source-reference/recovered-v12-controller.js preserves the original application controller separately from the new implementation; SOURCE_MANIFEST.json records extraction and dependency hashes for private review and is excluded from public bundles. The original application remains a prototype; the PDF.js authors retain credit for the bundled rendering library.

An additional recovered Page_Party.html was statically reviewed during cloud recovery. It belongs to the same local-PDF/page-advance utility family, with a different controller that includes page-range selection, synthesized celebration music and cancellation of overlapping rendering/celebration work. It is not identical to the v12 controller; direct code ancestry and chronology were not established. This package remains based on the previously recovered v12 workflow. No Page Party code or embedded library payload was copied into it, and the original Page Party application was not run.

Automated local Chrome checks passed for synthetic slide navigation, scoped keyboard handling, a generated two-page PDF, text extraction, final-page bounds, invalid-PDF recovery, restart and narrow layout. No external requests or page errors occurred. See VALIDATION.md. The demo does not claim full accessibility conformance.

Remaining limits

Optional audio/video codecs and autoplay behavior, fullscreen permissions, password-protected PDFs, large documents, non-Latin fonts and real assistive hardware need additional validation. PDF.js optional CMaps, standard fonts and WASM resources are not bundled; test representative documents before deployment. A license for the classroom project code has not yet been selected; the PDF.js Apache-2.0 license and attribution are preserved. This is a browser presentation tool, not a learner-tracking system.
