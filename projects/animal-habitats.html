Animal Habitats — recovered workflow, neutral demo

Creator and classroom workflow designer: Zachary Halaby. Developed and iterated with AI coding assistance.

An offline reading activity that keeps a short text visible while a teacher supports comprehension, letter recognition and word building. The demo shows adjustable answer fields, retries, word inspection, manual keyboard scanning and an explicit distinction between a response and teacher-supported completion.

This package was prepared from static review of the recovered Animal Habitats Smooth Reading archive. It is a reduced, source-derived portfolio demonstration: selected reviewed functions and interaction patterns are retained, while the interface and short practice texts are newly written. It is not the complete recovered classroom application.

Try it

Open index.html in a current desktop browser. No server, installation, account, media download or network connection is needed. Local Chrome was tested both through a temporary loopback server and directly as a file.

  1. Pick a fictional demo turn and a small, medium or larger choice field.
  2. Read the passage; select a printed word to inspect its letters.
  3. Answer, request a model, or use teacher-supported completion. Word inspection/model support is recorded only in memory and is not described as an independent response.
  4. Continue through the nine activities, or reset the demo at any time.

Tab and Enter operate native buttons. Right Arrow scans when a choice has focus; the two scan buttons provide the same manual sequence without a timer. The larger-text control and responsive layout provide additional access options. These features have not been assessed with assistive hardware or a screen reader.

The text-only fallback is intentional: a teacher can read aloud. The original prerecorded word/phoneme audio, narration, animation and illustrations are excluded rather than replaced by an external service. The demo does not claim to reproduce the original audio-assisted decoding experience.

Recovered design and changes

Static source review found a broader workflow involving a reading turn, word-level audio/help, question generation, support ratings, individualized goal references, recurring activity types, session storage and spreadsheet exports. Those findings describe code capabilities, not verified classroom use or outcomes.

The clean demo preserves comprehension, letter recognition and stepwise word building across three newly written habitat passages. source-core.js retains the inspected normalization, first-letter and deterministic shuffle helpers and adapts the original support-dependent answer-field pattern. app.js supplies a new neutral shell with safe DOM text rendering and memory-only state. lesson-data.js contains only new generic practice material.

Every original learner record, individual goal, class identifier, note, name binding, personalized celebration, stored-session mechanism, book image, embedded workbook and media payload is excluded. There are no free-text learner inputs, file import, export or persistent storage APIs. The fictional labels are controls, not anonymized people.

Verification and limits

Run the included offline core checks with an existing Node.js installation:

node tests/test-core.cjs

No packages are required. Validation also covered the complete browser route, support labels, scanning, reset, desktop/mobile layouts and direct file opening. See VALIDATION.md.

This demonstrates Zachary Halaby's classroom workflow design: configurable interactions and explicit support-state reporting. The recovered code does not establish deployment scale, accessibility conformance, learning improvement, IEP attainment or production readiness. Preparation and the new shell were also AI-assisted. Third-party media are excluded, and a project software license has not yet been selected.

See PROVENANCE.md, PRIVACY.md and LICENSE_STATUS.md. Nothing has been published by this preparation step.
