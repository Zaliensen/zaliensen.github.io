MettiFriends / Revenge of the Frogs — NFT contract experiments

Recovered 2022 Remix experiments explore two ERC721 minting workflows: a public paid mint and a mint gated by ownership of another token. The package explains the contract design without displaying or distributing NFT artwork. The recovered source spells the token-gated contract MettiFrens; MettiFriends is the user's project label.

This package contains no images, artwork, video, audio, NFT metadata collection or archive image assets. Old metadata URLs were replaced with a non-resolving placeholder, and nothing was downloaded from them. Token images are not part of the upload package.

Contracts and intended workflow

RevengeOfTheFrogs.sol uses the later active mintHELL variant: a maximum supply of 666, maximum mint request of 10 and historical declared cost of 15 ether per token. MettiFrens.sol uses an ERC20 balance gate and active mintMettiTokenHolderFRENs: supply666, request limit20 and historical cost25 ether. These are retained source constants, not current pricing or a sale offer.

Both allocate unused token IDs through RandomlyAssigned, expose token metadata URIs assembled from a base URL/token ID/.json, and restrict balance withdrawal to the owner. RandomlyAssigned.sol and WithLimitedSupply.sol are credited 1001.digital helpers; ERC721/enumeration/ownership come from OpenZeppelin. The declared royalty variable in MettiFrens does not establish an implemented royalty standard.

Recovery and cleanup

Only four selected Solidity members were extracted from Remix ZIP backups, each with filename/boundary/CRC validation. The two contract variants are deliberately kept distinct. Earlier commented-out mint variants and generic Remix tutorials are omitted. Helper author comments and MIT SPDX notices remain. A moving GitHub-master import was changed to the equivalent OpenZeppelin package import.

Historical content URLs are replaced with https://metadata.invalid/; the token-gate address is zeroed. Consequently, the MettiFrens mint path is intentionally unconfigured until a reviewer explicitly substitutes a disposable test token. Original archives and all images remain untouched.

Setup and verification

The recovered source declares Solidity^0.8.0 and depends on OpenZeppelin4-era APIs such as _exists and Counters; OpenZeppelin5 is not a drop-in replacement. The added review manifest pins OpenZeppelin4.9.1 and uses a local-only Hardhat/Solidity0.8.18 configuration. It is preparation scaffolding, not a recovered original build system.

Both contracts and helpers compiled offline using installed solc0.8.18/OpenZeppelin4.9.1. No mint, withdrawal, deployed-address lookup or marketplace integration was run. No original project-specific test suite was found in the selected source. A future disposable-chain test should verify supply/request caps, payment gating, metadata URI formatting, token-gate behavior and owner-only withdrawal.

Limits and contribution

Random assignment uses block-derived inputs and is not a cryptographic fairness guarantee. Payment/refund behavior, external token calls and withdrawal assumptions require security review. Artwork/metadata rights and original personal contribution are not established by possession of the backups. The user identifies the project; exact original authorship and any AI assistance remain unconfirmed. Third-party helper authorship is explicit and must not be presented as original work. See ATTRIBUTION.md, CHANGELOG.md and package-manifest.json.
