World Plate — restaurant learning game prototype

Creator and game workflow designer: Zachary Halaby. Developed and iterated with AI coding assistance.

A standalone, original-code-derived game with Egypt and Spain modes. The recovered application combines food reading and a quiz with ingredient sequencing, simulated restaurant service, menu pricing, operating costs, staff, upgrades and location progression. Open index.html in a modern desktop browser, or serve this directory with a local static server. No account, build step or dependency installation is required.

This package uses the later Stable Characters / Table Fix version sent July 23, 2026. It supersedes the earlier Reset Game build for this portfolio entry. The later version's geometric Egypt avatars, appearance controls, customer figures, empty-table seats and room decorations are retained. Earlier versions remain private rather than appearing as duplicate projects.

This is a personal learning/game prototype recovered for portfolio review. Creator attribution is based on Zachary Halaby's confirmation. The implemented workflow is reviewable, while classroom deployment, educational effectiveness and business accuracy have not been verified. The attribution does not claim sole manual coding.

What was preserved

The lesson/quiz, restaurant setup, recipe assembly, pickup and delivery, timed customer patience, menu price caps, daily profit display, staff wages, upgrades, city progression and home interactions come from the recovered game code. The public version retains these systems so a reviewer can discuss how a multi-step user workflow becomes visible actions and state transitions.

For a Deployment Strategist conversation, the relevant example is the flow from instructions to tasks, feedback and a reviewable outcome. The simulated cash, ratings, recipes and rewards are game rules. They are not real school records, measured adoption, financial analysis, or evidence of Palantir platform experience.

Public preparation changes

  • Removed all 212 embedded original media entries, including raster artwork and original SVG images. Rights to those assets were not established. The replacement artwork consists of 213 newly drawn, simple SVG placeholders, including a fallback image.
  • Retained the later application's code and layout, including its CSS-drawn Egypt characters, with targeted changes prepared with AI assistance. New SVG placeholders replace the original embedded art, including Spain sprites; the visual detail differs from the original.
  • Fixed restaurant/player labels to World Plate Demo and Demo Chef. Dish labels are also fixed, while menu prices remain adjustable. The demonstration does not collect names or free-text responses.
  • Changed every saved-game key to the separate portfolioDemo_worldPlate_v1_ namespace. This copy neither reads nor resets the original game's save keys. Only fictional game progress is stored locally in this browser.
  • Removed device speech synthesis; all help and feedback remains visible as text. Short generated game tones remain. There are no embedded voices, remote assets or network APIs.
  • Added a public-demo notice, focus indicators, reduced-motion styling and focusable play regions. Keyboard handlers preserve normal control activation and ignore inactive game screens.
  • Added a restrictive network policy. The original game uses inline button handlers, so inline scripts remain allowed; this is not a complete security-hardening rewrite.

Try it

  1. Select Egypt or Spain. Read the food cards, close the tutorial with Next/Done, and answer the five quiz questions. Wrong answers reveal the answer and advance; the quiz is practice, not an assessment record.
  2. Choose a placeholder avatar, keep the fixed demo labels and continue to the menu. Set prices within the current rating cap and save.
  3. Open the restaurant. Build an order by selecting its four ingredients in the displayed sequence. A wrong ingredient reduces the remaining assembly time by one second.
  4. Pick up the finished dish at the counter, move near its table, and deliver. Close the restaurant to inspect the game's revenue, ingredient cost, rent, wages and profit breakdown.
  5. Explore upgrades, staff, cities and the home after closing the restaurant. These are simulated progression systems.

Use Tab / Shift+Tab for native controls and Enter / Space for buttons. Focus the restaurant play area, then use arrow keys or W/A/S/D to move and Space to pick up or deliver. The on-screen movement controls provide another route. Focus the home play area for arrow-key movement there. The original interface includes timers, animated feedback and modals; full keyboard, screen-reader, switch-device and classroom usability testing remains outstanding. This is not an accessibility-conformance claim.

Game progress persists on this browser in the demo namespace. Use the title screen's per-mode Reset or Reset All to clear only this demonstration's saves. A different browser or origin has a different save area. No real purchases, payments, accounts or communications occur.

Validation and limits

Run node test_game.cjs for scoped behavioral checks of the public game code. Tests use simulated DOM/timers/storage, covering both modes' quiz behavior, fixed labels/price caps, all eight recipe sequences, pickup/delivery and duplicate-delivery guard, staff unlock/wages, daily expenses and save/reset isolation. They are not a substitute for real-browser visual and interaction review. verification.json records syntax, static media/privacy checks and behavioral results.

The source audit covered data declarations, external IO/storage/evaluation surfaces, free-text inputs, the asset resolver, keyboard handlers and the tested lesson/service/economy workflows. It was not a line-by-line certification of the entire recovered application. The original archive remains unchanged in private quarantine and was not run before audit.

The food descriptions and cultural setting text are inherited, simplified game content and have not received a subject-matter review. The game is not cooking instruction or an economic model. No field test, legal certification, accessibility certification, production deployment or external publication is claimed. No license for the recovered code or excluded assets is asserted by this preparation.
